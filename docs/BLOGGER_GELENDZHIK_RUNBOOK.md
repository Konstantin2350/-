# Запуск блогера: квартира в Геленджике

Ориентировочная дата выхода ролика: **27 августа 2026 года**.

## Что уже настроено в Оркестре

- Кампания: `Квартира в Геленджике — ролик блогера`.
- Код источника: `gelendzhik-blogger-2708`.
- Кодовая фраза клиента: `Геленджик 2708`.
- Целевой канал: WhatsApp.
- Норматив первого ответа: 5 минут.
- Лиды, их ответы, статусы и источник хранятся в базе Оркестра, без Bitrix.
- После получения телефона заявка автоматически попадает в очередь человека.

## Важное ограничение

Обычный WhatsApp на личном телефоне не отправляет сообщения в Оркестр. Ссылка и
кодовая фраза позволяют определить источник, но для полностью автоматического
ответа нужен WhatsApp Business API и его webhook.

До подключения Business API оператор может зарегистрировать обращение через
`POST /v1/webhooks/leads/gelendzhik-blogger-2708`. Это не теряет источник и
сохраняет единый реестр заявок.

## Шаг 1. Заполнить данные квартиры — сегодня

Подготовить один проверенный документ:

1. Цена и возможный торг.
2. Район и ориентир без публикации лишних персональных данных.
3. Площадь, этаж, количество комнат и состояние.
4. Документы, ограничения и форма расчёта.
5. Расходы покупателя и комиссия.
6. Доступные даты и время просмотра.
7. Фото, видео и ссылка на объявление.
8. Ответы на 10 частых вопросов.

Загрузить документ в базу знаний Оркестра через `/v1/knowledge/documents`.

## Шаг 2. Настроить ссылку — сегодня

В локальном `.env` указать:

```dotenv
PUBLIC_BASE_URL=https://домен-оркестра.example
BLOGGER_CONTACT_PHONE=79990000000
```

Реальный номер хранится только в `.env`, а не в Git. Ссылка для блогера:

```text
https://домен-оркестра.example/r/gelendzhik-blogger-2708
```

Она считает переход и открывает WhatsApp с готовым текстом:

```text
Здравствуйте! Пишу по квартире в Геленджике из ролика блогера.
Код: Геленджик 2708
```

## Шаг 3. Подключить входящие сообщения — сегодня или завтра

Предпочтительный вариант:

1. Подключить номер к WhatsApp Business API.
2. Указать callback:
   `/v1/webhooks/leads/gelendzhik-blogger-2708`.
3. Передавать `x-webhook-secret` и стабильный `external_id` диалога.
4. Преобразовать входящее событие провайдера в формат:

```json
{
  "external_id": "wa-dialog-123",
  "channel": "whatsapp",
  "message": "Хочу посмотреть квартиру, бюджет 15 млн",
  "name": "Анна",
  "phone": "+79990000000",
  "answers": {
    "budget": "15 млн",
    "timeline": "в течение месяца"
  }
}
```

Если Business API ещё нет, оператор вносит сообщение этим же запросом вручную.

## Шаг 4. Сценарий разговора

Оркестр последовательно уточняет:

1. Цель покупки: для себя, отдыха или инвестиций.
2. Бюджет.
3. Срок принятия решения.
4. Способ оплаты.
5. Удобное время просмотра.

После получения телефона Оркестр создаёт передачу человеку. Горячими считаются
запросы на просмотр, готовность купить, одобренная ипотека и быстрый срок сделки.

## Шаг 5. Ответственный человек — до теста

Назначить одного основного и одного резервного ответственного. Основной человек:

- забирает заявку из `/v1/operator/handoffs`;
- отвечает не позднее 5 минут;
- фиксирует статус через `PATCH /v1/leads/{lead_id}`;
- переводит лид в `viewing_scheduled`, `won` или `lost`.

## Шаг 6. Проверка — 26 августа

Провести не меньше пяти сценариев:

1. Только вопрос о цене.
2. Есть имя и телефон.
3. Горячий запрос на просмотр.
4. Повторное сообщение того же клиента.
5. Неверный код кампании или webhook-секрет.

Проверить:

- источник не теряется;
- повторное сообщение обновляет тот же лид;
- телефон нормализуется;
- передача человеку создаётся один раз;
- метрики доступны через
  `/v1/campaigns/gelendzhik-blogger-2708/metrics`.

1. За час проверить `/health`, ссылку и очередь операторов.
